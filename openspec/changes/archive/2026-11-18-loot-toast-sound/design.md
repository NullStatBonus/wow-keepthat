# Design

## Context

- `UI/Toast.lua`: `Toast.Handle` merges counts into an active or queued entry, else marks the item seen and queues it; `startNext` shows up to three. `Toast.Demo` builds samples (Preview, `/kt test toast`, `/kt demo`).
- Settings live in `Core/Defaults.lua` (AceDB fills missing keys, so upgrades get defaults). Appearance's Loot toast group is in `Options/Options.lua`. The `/kt set` registry (`Core/Presentation.lua`) handles only boolean and integer keys.
- Don't Do That already has a sound picker (`Model/SoundList.lua`, `Data/Sounds.lua`, `UI/Alert.lua`): built-in entries, LibSharedMedia entries keyed `lsm:<name>`, fallback to the default, `willPlay` check. KeepThat reuses that shape.

## Goals / Non-Goals

**Goals:** see proposal and specs; plus no new library, no new file in `Libs/`, no new Integrations-page row.

**Non-Goals:**
- `/kt set` keys for sound or channel. The registry would need an enum type; the settings page is enough. README's public-key list stays unchanged.
- A font choice.
- Music, Ambience and Dialog channels (Don't Do That offers them; for a loot cue Master and Sound effects cover it).
- Probing sounds in `/kt probe` (it would play ten sounds). The test plan covers hearing each one.

## Decisions

### D1. Built-in list in `Model/Sounds.lua`, played by kit ID
Plain-Lua table: `{ key, label = L[...], id }` in picker order, `default = "auction"`, `none = "none"`. Keys are stable strings (`auction`, `levelup`, `questcomplete`, `readycheck`, `raidwarning`, `pvpqueue`, `murloc`, `bellalliance`, `bellhorde`, `bnettoast`) so saved choices survive relabeling.
Play by numeric ID, not `SOUNDKIT` constant name: Level up and both bell tolls have no Era constant, and the IDs are verified on both builds. Alternative (Don't Do That's `constName` filter) would drop three of the ten on Era.
Not in `Data/`: that folder is generated by `tools/`; this list is hand-curated.

### D2. Resolve is plain Lua; playing is in the adapter
`Sounds.Resolve(key, packs)` → `"kit", id` | `"file", path` | `nil`. `packs` is a name → path table from the adapter, so tests pass a fake.
`Sounds.Effective(key, packs)` → the key that will play: the saved key if it resolves, else the default. Used by the dropdown's `get` so a missing pack shows Auction open without overwriting the saved key.
`Sounds.Play(key, channel, adapter)`: None → no-op; else resolve the key, play; if it did not resolve or `willPlay` is false and key ≠ default, try the default. Returns whether something played.

### D3. `Core/Adapter_Sound.lua`
- `A.PlaySound(id, channel)` / `A.PlaySoundFile(path, channel)`: `pcall`, return `willPlay` (`nil` when the function is missing).
- `A.SoundPacks()`: name → path from `LibStub("LibSharedMedia-3.0", true)`'s `HashTable("sound")`, excluding `"None"`; `nil` when absent or it errors.
- Channel passed through only if `"Master"` or `"SFX"`, else Master.

LibSharedMedia is read in the adapter, not as an `Integrations/` module. It is a shared library other addons register into, not an addon with UI surfaces to hook; there is nothing to turn off besides the read itself, which is guarded and returns nil. The debug report gains one line, `sound packs = <count>` or `sound packs = none`, under Presentation, so a missing library is visible.

### D4. When the sound plays
In `Toast.Handle`, after `Toast.seen[itemID] = true` and the queue insert, before `startNext`: `Toast.Chime(now)`. Count merges return earlier, so they are silent. Playing at acceptance (not display) keeps a burst at one sound even though toasts 4 and 5 display about 4 s later (spec "One sound per loot burst").
Cooldown: `Toast.SOUND_COOLDOWN = 2` seconds, `Toast.lastSound` holds the time of the last real-loot play; time from `A.Now()` (`GetTime`). Unknown time (nil) → play and do not record.
Samples: `Toast.Demo` plays once per call via `Sounds.Play` directly, not touching `lastSound`.

### D5. Settings and picker
Defaults: `toastSound = "auction"`, `toastSoundChannel = "Master"`.
Two `select` controls in Appearance > Loot toast, after Scale: **Sound** and **Sound channel**, disabled when the toast is off (like opacity and scale), with the existing off-note extended to mention sound.
- `values` is a function (packs register after login), `sorting` gives D1 order then packs alphabetically, labels `L["%s (sound pack)"]`.
- `get` returns `Sounds.Effective`; `set` saves and plays the choice once (except None).
- Channel values: `Master` → `L["Master"]`, `SFX` → `L["Sound effects"]`.
Codex reviews the group layout before it is called done (project practice for visual and menu changes).

## Risks / Trade-offs

- [A game patch removes or renumbers a kit] → `willPlay` false → default plays; test plan rechecks each sound per client; `docs/contracts.md` records the builds verified.
- [Players find any sound annoying] → toast is off by default; None is one click; one sound per 2 s burst.
- [Master ignores the player's sound-effects mute] → that is the point of the default; Sound effects is offered.
- [LibSharedMedia returns a path that no longer exists] → `PlaySoundFile` `willPlay` false → default plays.

## Migration Plan

Nothing to migrate: AceDB supplies the two new defaults to existing profiles, so upgraders hear Auction open once they have toasts on. Rollback: earlier versions ignore the two keys.
